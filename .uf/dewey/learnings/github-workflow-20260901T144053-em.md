## Issue Template and Description Requirements

### Issue Creation Standards
- All issues MUST have a clear title following the pattern: `<type>: <brief description>`
- Issue body MUST include acceptance criteria as a checklist
- Issues SHOULD reference related issues/PRs using GitHub linking syntax

### Description Structure
1. **Problem Statement** — What is wrong or what is needed
2. **Acceptance Criteria** — Checkboxes for each requirement
3. **Context** — Background information, links to specs or discussions
4. **Notes** — Implementation hints, constraints, non-goals

### Labels
Apply appropriate labels at creation time:
- Type: `bug`, `enhancement`, `docs`, `chore`
- Priority: `P0`, `P1`, `P2`
- Size: Use T-shirt sizes (XS, S, M, L, XL)

### Project Board Assignment
Issues MUST be added to relevant project boards at creation time.
