When creating pull requests in the unbound-force organization, three metadata requirements must always be followed: (1) The `llm_assisted` label MUST be added to any PR where an LLM was involved in the creation process — this is a mandatory attribution label, not optional. (2) Labels, milestone, and priority from the originating GitHub issue MUST be inherited by the PR — check the issue with `gh issue view N --json labels,milestone` and apply matching labels and milestone to the PR with `gh pr edit`. (3) The PR MUST be added to both the "Unbound Force Planning" project (unbound-force org, project #3) and the "Compliance Automation planning" project (complytime org, project #14), and its status in both projects MUST be set to "Ready for Review" upon creation. Use `gh project item-add` to add to projects and `gh project item-edit` to set the status field. The `gh` CLI requires the `project` scope — if missing, run `gh auth refresh -h github.com -s project` first.
