ComplyTime Intake & Delivery Process — 7-Step Workflow. Applies to greenfield or cross-cutting feature requests requiring product discovery, requirements breakdown, and new or major changes. Component-scoped requests use normal GitHub Issue and PR flow.

The 7 Steps:
1. Feature Request & PRD (Track 1, Product Owner → Merged PRD + Technical Owner named)
2. Technical Design & Architecture (Track 1, Technical Owner → ADR/design artifacts)
3. AAC Review & Acceptance (Track 1, AAC → Merged ADR)
4. Story Breakdown "The Bridge" (Bridge, PgM + TO → High-level User Stories + estimates)
5. Kickoff & Scope Alignment (Track 2, PgM + Stakeholders → Locked scope baseline)
6. Story Sizing (Track 2, PgM/Tech Lead/TO → Sized stories + release timeline)
7. Execution, Review & Retrospective (Track 2, PgM → Delivered milestone; UAT started)

Key roles: Product Owner, Technical Owner (floating per-initiative), Tech Lead (workstream-level), PgM (pipeline facilitator/gatekeeper), AAC (Architecture Advisory Council), Engineering Manager, Steering Committee, Core Execution Team.

Escalation: All urgent requests go to PgM (The Gatekeeper). Emergency enters active release only for production-stopping bugs or immediate compliance/legal blockers. "One In, One Out Rule" — equivalent scope pulled out.

Execution driven by OpenSpec: `/openspec:proposal` → proposal/design/tasks → `/unleash` for autonomous pipeline.
