## PR Submission Checklist (unbound-force org)

When submitting a PR in the unbound-force org, complete ALL of the following:

### 1. Labels
- Add `llm_assisted` label to ALL PRs created with AI assistance
- Carry over labels from the linked issue (e.g., `docs`, `next-release`)

### 2. Assignment
- Assign the PR to the same user(s) as the linked issue

### 3. Project boards
Add the PR to BOTH org project boards using GraphQL API (`gh project item-add` silently fails for cross-org projects):
- **Unbound Force Planning** (org: unbound-force, project #3, ID: PVT_kwDOD616js4BaE-9)
- **Compliance Automation planning** (org: complytime, project #14, ID: PVT_kwDOCtVpQc4Ber79)

### 4. Priority and Size inheritance
Copy the **Priority** and **Size** fields from the linked issue to the PR item on each board. Query the issue's item fields first, then set the same values on the PR item using `updateProjectV2ItemFieldValue`.

### 5. Status at PR submission time
- **PR** → "Ready for Review" on both boards
- **Issue** → stays "In Progress" on both boards (transitions to "Done" only after PR merges)

"Ready for Review" means waiting for a human reviewer. "In Review" means a reviewer has actively picked it up — do NOT set this yourself.

### 6. Status at work start time
When starting work on an issue, set the issue to "In Progress" on both boards BEFORE starting implementation.

### 7. GraphQL API reference
Use `addProjectV2ItemById` mutation with the PR's node ID (from `gh pr view --json id`) and the project's node ID.
